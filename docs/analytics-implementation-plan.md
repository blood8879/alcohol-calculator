# Analytics implementation plan

This release adds consent-gated GA4 events, route and engagement measurement, content and conversion events, and ad lifecycle events. The app uses its existing Firebase Android and iOS streams and does not create a new Firebase project.

| Lane | Owner | Deliverable | Status |
| --- | --- | --- | --- |
| Foundation | Analytics foundation | Native startup defaults, consent gate, event schema, screen views and notification opens | Source and tests complete |
| Content and calculator | Content worker | Finite content discovery and calculator outcome events | Source and tests complete |
| Engagement | Engagement worker | Session, quiz, challenge, and weekly-goal events | Source and tests complete |
| Advertising | Ads worker | Banner/interstitial/rewarded lifecycle events with finite placement and failure reasons | Source and tests complete |

As of September 23, 2026, the integrated consent privacy-options entry, reactive ad-permission state, and ad-surface gate passed 115 tests in 26 suites, TypeScript, and lint. The final signed production Android AAB for app 1.2.5/versionCode 25 passed artifact and signature validation; its source and SHA-256 were verified after the isolated QA build. The user submitted it to Google Play, where it is under review. The Android AdMob app ID matches the console-confirmed Play package association. GA4 console setup has 27 custom definitions and a verified AdMob link. The authenticated GA4 report for August 26–September 22, 2026 showed 23 users and 168 events; its $0 revenue does not establish zero AdMob earnings. AdMob independently showed $0.03 from 33 impressions in the last seven days. The conditional post-release analysis is in [the growth roadmap](analytics-growth-roadmap.md).

The final AAB-derived production APK ran on an Android emulator: home loaded and a valid 500 ml 5% beer calculation showed 140 kcal (QA screenshot: `/tmp/alcohol-consent-production-result.png`). Its native schema-2 events received HTTP 204 from the collection endpoint (QA log: `/tmp/alcohol-consent-production-native.log`); a bounded final console check did not show those exact events, so console receipt remains unconfirmed. An earlier native pass also rejected zero input, expanded an encyclopedia entry, advanced the daily quiz, and saved a beer entry in the tracker. UMP is published for the corrected AdMob app ID; GA4 DebugView displayed 52 events in earlier pipeline QA. A separate forced-EEA release APK exists solely for QA and must never be uploaded. On September 23, its first form load timed out and collection failed closed; after a warm restart, the form appeared, “Do not consent” was selected, and native collection remained disabled (QA log: `/tmp/alcohol-eea-rejected.log`). Accept and privacy-options reopen checks remain pending. Native startup collection settings require the new binary; an over-the-air JavaScript update alone cannot apply them. iOS source settings are included, but signed iOS validation is outside this Android release because signing identities are unavailable.
